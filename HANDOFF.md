# Handoff — Multi-AI Terminal (MAT)

Current released line: **v0.2.10**. Updated 2026-07-23 after completing the BAT runtime continuation through #25. Audience: the next implementer (a coding agent or human) taking over development. When this file disagrees with the code, the code wins — then fix this file.

## What this is

MAT is a desktop workbench that orchestrates **headless coding-agent runtimes** (claude, codex, grok, agy, OpenRouter through Codex-as-runtime, plus a deterministic `mock`) through declarative multi-stage workflows: parallel fan-out per stage, an LLM orchestrator gating stage transitions, verification contracts producing evidence, handoff context between stages, mid-run steering, and exportable debug bundles. UI is React in a Tauri v2 shell; the server is Fastify driving child processes. **No PTY by design** — production Claude uses the Agent SDK, production Codex uses persistent `app-server` JSON-RPC, Grok/Agy retain headless CLI transports behind managers, and OpenRouter reuses the Codex runtime. One-shot Claude/Codex adapters remain explicitly selectable legacy paths.

The owner and sole user is Ted Huang (`teddashh/multi-ai-terminal` on GitHub). He runs Windows daily; the dev box is Linux. The product thesis (roundtable consensus, 2026-07): the moat is **evidence and handoff quality** — what an agent proved, what the next agent receives — not UI breadth.

Preserve the smooth desktop first run: startup quietly bootstraps missing supported Codex then Claude managed runtimes through one fixed catalog-pinned, integrity-verified server coordinator, writing only below `<dataDir>/runtimes/`. The web client must not launch a second bootstrap sequence. Do not turn this into a user-visible flag, per-provider confirmation, or repeated Setup flow. Setup remains the visible recovery path. Provider-specific recipes, updates, and sign-ins remain fixed product actions with no user-supplied command line. The agent source lane never installs tools and never calls install/update/sign-in endpoints on the user's behalf.

## UX references — principles, not scope

The v1.4 UI work checked the heads available on 2026-07-20 for [TempoTerm](https://github.com/mukiwu/tempo-term) (`0bed0f9`), [Better Agent Terminal](https://github.com/tony1223/better-agent-terminal) (`b09639c`), and MAT's predecessor [multi-ai-chat-desktop](https://github.com/teddashh/multi-ai-chat-desktop) (`4e98c06`, the v1.7.0 merge). Provider-runtime implementation was subsequently grounded against BAT `0e24800`; the v0.2.10 #24/#25 work checked that baseline again and found it unchanged. TempoTerm and multi-ai-chat-desktop are hierarchy/status/focus interaction references, not architecture templates. BAT is more than that — see its bullet:

- **TempoTerm:** borrow project-first navigation, glanceable agent/worktree status, stable docked panels, and actions placed next to the context they affect. Do not import its PTY, editor, file/Git/SSH, split-pane, or general IDE breadth.
- **Better Agent Terminal:** Ted's standing instruction (restated 2026-07-22): **hew to BAT for agent-runtime handling and track its updates** — BAT is the architecture reference for provider sessions, not merely a UX reference. At head `0e24800` it drives codex through a persistent `codex app-server` JSON-RPC/JSONL controller (`src-tauri/src/codex_app_server.rs`: threads, `turn/interrupt`, approval policies, idle-connection reaper, `account/rateLimits/read`) and claude through `@anthropic-ai/claude-agent-sdk` in its node-sidecar. BAT has no automatic production CLI failover; MAT likewise keeps one-shot Claude/Codex adapters only as explicitly selected legacy modes. On the UI side, borrow a dominant working surface, presets for the common path, and compact status that expands on demand; do not import terminal aggregation, remote clients, or its full feature catalog. (An earlier revision of this file listed "SDK session semantics" under do-not-import — that was an implementer over-generalization of UI scoping, corrected by Ted on 2026-07-22. Never cite it as an architecture ban.)
- **multi-ai-chat-desktop:** preserve the owner's familiar conversation-first hierarchy, visible workflow controls, readable results, replay/diagnostic affordances, and streaming UI that does not steal focus or let stale async responses replace a newer choice. Do not reuse its WebView automation runtime or broaden MAT into parallel chat windows.

The synthesis is: adopt the hierarchy/status/focus mental model so setup, diagnosis, and evidence reading feel direct and predictable while keeping MAT headless. Product depth still means trustworthy evidence and handoff, not more panes or terminal emulation.

## Repo map (the load-bearing parts)

- `shared/` — strict zod contracts shared by server and web; evolve persisted contracts **additively only**. `providerEvents.ts` is the BAT-compatible provider-neutral 19-event manager surface; all events carry `sessionId`, `status` is full-shape, and a turn has exactly one `turn-end`. Current production managers use its content-only compatibility ingress; the richer reserved shapes do not make their corresponding features reachable. `events.ts` remains the durable `AgentEvent` schema; the manager surface does not own `id/seq/ts`.
- `server/src/runtime/{catalog,install,resolve,triggers}.ts` + root `runtime-catalog.json` — pinned Claude/Codex/Node runtime metadata, integrity verification, safe extraction, atomic swap/rollback, managed/external resolution, the single Codex→Claude startup-bootstrap coordinator, and serialized mutation endpoints. Installs write only under `<dataDir>/runtimes/`; there is no host-global install, PATH edit, or elevation.
- `server/src/spawn.ts` — `augmentedPathEnv()` discovers existing well-known CLI dirs without editing the host environment. It also preserves the **cross-spawn bypass**: `options.shell ? spawnChild : crossSpawn` — cross-spawn fakes ENOENT on exit-1 under shell on Windows.
- `server/src/adapters/base.ts` — spawn/probe plumbing; version probes allow 15 s on Windows / 8 s elsewhere, share in-flight work, cache successes 10 minutes and transient failures only 2 seconds. A probe normally settles on `close`, but also settles 500 ms after `exit` and releases its pipe ends: a CLI helper inheriting stdout must not turn a successful version line into a timeout. `providerSpawnSlot()` per-provider promise chain spaces same-provider spawns ≥1500 ms (mock exempt); `detectAuthFailure()` pattern-scans the last 4 KB of output and composes `errorReason` + `Fix: <signInCommand>` + the CLI's own instruction line (api-key **values** filtered out).
- `server/src/adapters/{claude,codex,grok,agy,openrouter,mock}.ts`, `registry.ts` — the content-only adapter boundary. Claude/Codex choose production session or explicit legacy mode; Grok/Agy delegate to managers; OpenRouter declares `runtimeFamily:'codex'` and an environment-credential presence probe rather than inventing an OpenRouter binary. `mock.ts` remains manager/stagger/auth exempt.
- `server/src/providers/claude/` — Agent SDK loader, persistent LiveQuery/session runtime, and read-only account index. `server/src/providers/codex/` — shared app-server connection, thread/turn ownership, translation, runtime, models, account store, and API-key chain.
- `server/src/providers/cli/manager.ts` + `providers/{grok,agy}/` — common FIFO manager over existing streaming-JSON/plain transports; Grok is resumable, Agy is not. `providers/openrouter/` — bounded live/stale/fallback model catalog, an isolated Codex home where MAT writes only fixed provider config, and a Codex runtime profile; the UI selects model then version and stores the exact selected slug.
- `server/src/providers/contract.ts` — the single manager-to-evidence bridge. It validates the 19-event compatibility surface, builds full session meta, canonicalizes tool names, projects content/technical status, suppresses provider history replay, enforces exactly-one `turn-end`, and returns terminal metadata to nodeRunner rather than appending a second lifecycle sequence. Production managers currently feed `AdapterContentEvent` through `acceptContent()`; native rich manager emitters remain future work.
- `server/src/providers/install.ts` — fixed provider/platform recipes used only after an explicit Setup click where no managed runtime action is available. User data never reaches a command. `POST /api/providers/refresh` accepts no user data, clears discovery caches, and reruns probes. `providers/auth.ts` owns auth alerts and canonical sign-in guidance.
- `server/src/providers/signin.ts` — the in-app login driver. Fixed per-provider recipes (command, args, trusted hosts, optional status probe); single active session; URL scraping accepts only `https:` on an exact/subdomain trusted-host match; pasted codes go **only** to the CLI's stdin; excerpts pass `redactEnvironmentValues`; diag records outcome metadata but never URL/code/output. The whole ceremony times out below codex's 15-minute device-code expiry. Tests drive it through fake `claude`/`codex` executables on PATH (`server/test/signin.test.ts`).
- `server/src/engine/` — `runManager` → `stageRunner` → `nodeRunner`. `nodeRunner` wraps every real adapter in `ProviderTurnBridge`, preserves one ordered content/technical queue until `spawned`/`running`, stamps all evidence identity, and remains the only lifecycle writer; provider terminal metadata is folded into its one result path. It also owns stall/auth detection and output tails. `verify.ts`, `report.ts`, `debugBundle.ts`, `worktree.ts`, and `steer.ts` remain the evidence/artifact plane.
- `server/src/diag.ts` — structured diag journal. **Never log environment-variable values** anywhere, including here.
- `web/src/app/App.tsx` — boot/API and active-run WebSocket lifecycle, global connection/run status, Abort, and the Health entry point. Transport status and evidence completeness are different signals; do not collapse them into one green/red light.
- `web/src/app/AppShell.tsx` — the load-bearing v1.4 geometry: 84 px icon+text rail → persistent Launchpad → persistent activity inspector → flexible Run Workspace. Launchpad and inspector collapse by hiding their inner content, **not by unmounting their trees**, so drafts and dialogs survive. Independent widths live in `mat-shell-layout-v2`, persist after a 120 ms debounce, have keyboard-accessible dividers, and are fitted to retain a 320 px workspace. Keep the outer grid cells present when collapsed; removing them changes CSS grid auto-placement and can hide the workspace.

## Invariants — do not break

**Security (user-facing trust):**
1. Desktop startup may quietly bootstrap missing supported Claude/Codex runtimes through the fixed catalog-pinned, integrity-verified installer. Remaining provider installs, updates, and sign-ins use the fixed actions in `providers/install.ts` and `providers/signin.ts`. User input never reaches a command line — the pasted OAuth callback code goes only to the login child's stdin. The managed installer never modifies host PATH/toolchains and writes only below `<dataDir>/runtimes/`; any provider-specific manual action remains separately labeled.
2. Never log values **read from the environment** — not in diag, errors, bundles, or transcripts. Sink redaction removes every exact-field match and distinctive embedded machine value, plus credential-bearing values at every length; trusted engine constants and protocol enums remain intact when a host value merely coincides. The auth instruction passthrough accepts only canonical sign-in instructions.
3. The Codex unified-account feature is MAT's only provider credential-store boundary. It is limited to `<dataDir>/codex-accounts/**`, `<dataDir>/codex-accounts.json`, `<dataDir>/openai-api-key.bin`, and the shared `CODEX_HOME/auth.json`; it runs only from explicit account/API-key actions or the defined Codex snapshots (before login, after login, and shutdown sync). Account ids are path segments: only `[A-Za-z0-9_-]{1,128}` ids exist (unsafe `auth.json` account_ids are hashed, unsafe index entries dropped, unsafe request ids refused), so no store operation can resolve outside the boundary. Switching replaces only `auth.json` and never touches sibling config, sessions, memory, or cache; because OAuth refresh tokens rotate in the shared home, switch re-snapshots the outgoing account first and a same-target switch re-captures instead of restoring a stale copy. Success-path `markActiveValid` is suppressed while an API key is configured (the key, not the OAuth tokens, may have carried the turn). Sign-in, turns, and account mutations mutually refuse while another is active, with the sign-in reservation taken synchronously at start; the residual check-then-act window between two operations that both passed their guards is accepted for this single-user product, and a crash before the shutdown sync can lose the newest rotation until the next capture. In OpenRouter's isolated Codex home, MAT writes only the fixed provider configuration and never places `auth.json` or key bytes there; Codex may own runtime/session state beside that config. `OPENROUTER_API_KEY` reaches only the child environment and is never persisted by MAT. No credential values, tokens, JWT claims, or environment values may reach logs, diagnostics, bundles, or transcripts. Other provider credential stores remain CLI-owned.

**Determinism:** the `mock` provider stays exempt from real-provider behaviors (spawn stagger, auth alerts/`errorReason`) so tests and instruments stay fast and deterministic. The `MOCK_AUTHFAIL` instrument depends on this.

**Contracts:** `shared/` schema changes are additive-only. Provider-manager `status` is always full-shape and every started provider turn has exactly one `turn-end`; `nodeRunner` remains the sole lifecycle/evidence mapper and `eventLog` the sole `id/seq/ts` authority. All product-version manifests and npm lock metadata must agree; `npm run verify:version` enforces this and release builds also compare the tag.

**Agent lane (`agent-release.json` is a promise):** skills stay explicit-only (`disable-model-invocation: true` / `allow_implicit_invocation: false`). Lifecycle scripts never install host toolchains, modify PATH or shell profiles, elevate privileges, read provider credentials, or upload logs/audits; stop and status act only on identity-verified runner processes and refuse foreign or unverifiable PIDs; `--clear-invalid-state` removes only inspected corrupt state, never a process. The skills never drive the launched server's provider install/update/sign-in APIs on the user's behalf. The security invariants above apply unchanged to anything reached through the served UI.

**UI regressions with history:** stable zustand selectors; `min-h-0` on every flex/grid ancestor of a scroll pane; BAT-style follow mode (auto-follow disarms on wheel-up, re-arms at bottom); multi-line amber `errorReason`; no datalist; no ModelEditor auto-collapse.

**Live/replay evidence contract:** persisted `AgentEvent.seq` is authoritative and events are immutable. Conversation is a projection only: compatible adjacent continuations may become one block, but each source event appears exactly once and gaps remain visible. Timeline retains raw events and permits only reversible adjacent visual grouping. Live WebSocket gaps and initial/reconnect catch-up set a visible integrity state, backfill through REST, merge/deduplicate by sequence, and become `incomplete` with explicit Retry on failure. A transport connection badge does not prove evidence continuity. Historical selection never changes the active subscription, replay requests carry generation guards, and the server/debug bundle remain the complete record when the browser ring trims old rows.

## Release playbook

1. Bump the version in the **six authoritative files**: `package.json`, `server/package.json`, `web/package.json`, `desktop/src-tauri/tauri.conf.json`, `desktop/src-tauri/Cargo.toml`, `server/src/version.ts`. Then run `npm install --package-lock-only --ignore-scripts` to synchronize the root/server/web version metadata in `package-lock.json`. Leave `Cargo.lock` absent under the current policy — `release.yml` builds without `--locked`.
2. Run `npm run verify:version`, commit, push, and watch `ci.yml` for the pushed sha until **both** platforms are green.
3. `git tag vX.Y.Z && git push origin vX.Y.Z` → `release.yml` verifies the tag, reruns the Linux quality/evidence gates, builds four platform jobs, and creates a **draft** release with artifacts.
4. Attach bilingual notes to the draft (English then 繁體中文, same structure; voice: what changed and why it matters, driven by the field evidence that motivated it): `gh release edit vX.Y.Z --notes-file <notes.md>`.

## Windows/CI portability rules (each cost real debugging time)

- New tests that spawn processes or cycle worktrees need explicit timeouts (`, 30_000`) and deadline-based waits — vitest's 5 s default fails only on Windows CI.
- When injecting an `exists`/path predicate into tests, use **pure-POSIX fixture paths** and fake fs — `join()` produces backslashes on Windows while production template strings produce forward slashes; string equality silently diverges (`existsSync` tolerates mixed separators, hiding it locally).
- Compare workspace paths against the canonical path returned by the store/API, not the raw `mkdtemp` string — Windows can create the fixture through an 8.3 path such as `RUNNER~1` and resolve it back to the long user name.
- Fixture repositories that assert patch/file bytes must set local `core.autocrlf=false` — otherwise the Windows runner can rewrite LF to CRLF during `git apply` even though the patch is correct.
- Recursive removals: `rmSync(dir, { recursive: true, force: true, maxRetries: 10, retryDelay: 100 })` — Windows holds file locks briefly.
- `.cmd` shims need `shell: true` to spawn; that path must keep using raw `spawn` (not cross-spawn) or exit-1 becomes a fake ENOENT.
- jsdom lies about rendering — the real-browser smoke (`smoke:browser`) exists because jsdom hid a total black screen for four releases. Never remove it from CI.

## Known issues & upstream context

- **codex OAuth refresh tokens are single-use**; parallel same-account sessions race the rotation and the whole grant gets revoked ("refresh token was revoked") — upstream openai/codex#9634, #6498, #15502.
