# SPEC v1.0 → v1.1 — 4-Model Panel Review Record

Date: 2026-07-18. Reviewers ran independently on SPEC v1.0; all findings below were merged into SPEC v1.1 (a few consciously simplified: token auth optional instead of mandatory, dirty-worktree warning instead of fail-fast).

## codex-gpt-5.6-sol — verdict: revise

The product shape is coherent, but the execution contracts are not yet strong enough for independent one-shot module builders to converge. Provider coverage, attempt identity, persistence ordering, crash recovery, remote security, and missing API payloads must be made normative before implementation.

- **[BLOCKER] §2, §3.2, §4.0** — The "provider-agnostic" node contract promised in §0 requires `command`, `cwd/worktree`, and `parserTier`, but `AgentBinding`, `Slot`, and `AdapterSpawnArgs` contain different subsets; builders cannot agree on where executable overrides, parser selection, or working-directory policy live
  - fix: Define one normative resolved-node contract, including executable/argv policy, parser tier, resolved cwd, environment overrides, and precedence between provider defaults, workflow bindings, and run overrides.
- **[BLOCKER] §3.2, §4** — `gemini` is a valid provider with an owned adapter file and UI presence, but has no command, flags, event mapping, permission mapping, resume behavior, or declared parser tier
  - fix: Fully specify and fixture the Gemini adapter, or remove `gemini` from every v1 contract and UI surface.
- **[BLOCKER] §8, §9** — The server is described as localhost-only while the primary story accesses it remotely over Tailscale; no bind-address, authentication, origin policy, or trust boundary is defined
  - fix: Add `--host` with safe defaults, document Tailscale exposure, require authentication for non-loopback binding, validate WS/HTTP origins, and protect every mutation endpoint.
- **[BLOCKER] §5, §7** — Active-run crash recovery is unspecified: after restart, persisted nodes can remain `running` forever, child PIDs are lost, queues disappear, and worktrees may be orphaned
  - fix: Define startup reconciliation that marks interrupted attempts terminal, records a recovery event, cleans process/worktree state, and exposes an explicit resume/retry policy.
- **[BLOCKER] §5, §8** — "Retry stage" is an allowed v1 human intervention, but no REST operation or engine transition exists for it; the UI also has no specified control
  - fix: Add a stage-retry endpoint and contract defining eligible run states, selected nodes, attempt numbering, context reuse, worktree handling, and behavior when processes are still live.
- **[BLOCKER] §5, §7** — Retries reuse `nodeRunId`, while `NodeRun` stores only one attempt and raw logs, patches, branches, and worktree paths are keyed solely by that ID; attempts will overwrite or contaminate one another
  - fix: Introduce immutable `nodeAttemptId` such as `<nodeRunId>.a<N>`, persist attempt history, and key raw logs, artifacts, sessions, branches, and worktrees by attempt.
- **[MAJOR] §3.1, §4.0, §5** — Lifecycle ownership is contradictory: adapters "MUST emit" spawned/result events, yet process exit and timeout belong to the runner, `NodeOutcome` is undefined, and both layers can emit terminal events
  - fix: Define `SpawnedNode` and `NodeOutcome` schemas and assign exactly one owner for spawned/running/result/error/status transitions, including ordering and exactly-once terminal guarantees.
- **[MAJOR] §5, §10** — Worktree artifact capture is incomplete: `git diff` omits untracked files, "stage base" is undefined, retry reuse can include prior changes, and review-stage agents are not told how to access patches from isolated trees
  - fix: Record the exact base commit, capture tracked and untracked changes into a validated binary-safe patch/bundle, create fresh attempt worktrees, and define patch paths/content supplied to downstream prompts.
- **[MAJOR] §7** — Concurrent event append, sequence assignment, snapshot rewrite, and WS broadcast have no serialization or durability contract; parallel nodes can duplicate/reorder `seq`, broadcast uncommitted events, or leave snapshots ahead of logs
  - fix: Specify a per-run single-writer queue with append-before-broadcast ordering, monotonic sequence recovery from disk, fsync policy, and snapshot/event consistency rules.
- **[MAJOR] §5** — Stall semantics are not a state machine: `stalled` is nonterminal, but recovery on the next event is undefined, repeated timers may emit duplicates, and "all nodes terminal" is not formally enumerated
  - fix: Define terminal statuses, one-shot stall transitions, automatic `stalled → running` recovery on activity, timer cancellation, and join behavior for killed/failed/timed-out nodes.
- **[MAJOR] §6** — The orchestrator is treated as one per-run node but is absent from `RunSnapshot.nodes`; its ID is the constant `orchestrator`, gate attempts are indistinguishable, and its own normalized stream/session persistence is undefined
  - fix: Model each orchestrator invocation as a persisted node attempt with stable IDs, lifecycle events, usage, session reference, and explicit association to a gate decision.
- **[MAJOR] §3.2, §8** — `POST /api/runs` accepts undefined `overrides?`, even though the UI must alter workflow slots and orchestrator settings without mutating built-ins; independent frontend and API workers will invent incompatible payloads
  - fix: Define a zod schema for run overrides, whether it contains a complete frozen workflow or a constrained patch, validation rules, and persist the fully resolved workflow inside the run.
- **[MAJOR] §8, §9** — Required UI data has no API: "view patch" lacks a patch-content endpoint, workspace validation/is-git response is unspecified, and live/history run discovery does not define pagination or running-state filtering
  - fix: Add explicit response schemas and endpoints for artifact retrieval, workspace validation metadata, and cursor-based run history.
- **[MAJOR] §4.2** — Codex resume drops model, effort, sandbox, cwd, and permission arguments, and the spec does not say whether resumed execution inherits them; retries may run with different privileges or in the server directory
  - fix: Pin the verified resume argv order in fixtures and explicitly pass or verify cwd, sandbox, model, effort, and permission settings on every resumed turn.
- **[MAJOR] §5.1** — The digest guarantees at least 2,000 characters of result text per candidate while imposing a 24,000-character total cap, but workflows allow up to eight instances per slot and multiple slots, making the guarantees mathematically incompatible
  - fix: Define a deterministic token-budget algorithm with a maximum candidate count, per-candidate proportional allocation, ordering, truncation markers, and overflow behavior.

## agy-gemini-3.1-pro — verdict: revise

The spec has fundamental workflow stoppers in its Git worktree management and process lifecycle that would guarantee crashes on retries or timeouts. Additionally, the event data model and adapter assumptions require tighter constraints to ensure the streaming UI can actually render coherent messages and tool executions.

- **[BLOCKER] §5** — Worktree patch generation misses untracked files
  - fix: The engine must run `git add -A` inside the worktree before executing `git diff`, otherwise new files created by the agent will not be included in the patch artifact.
- **[BLOCKER] §5** — Node retries crash on existing git worktree
  - fix: When retrying a node, the attempt increments but `nodeRunId` stays the same; the engine must `git worktree remove --force` the old directory and delete the branch before spawning the retry, or `git worktree add` will fatally crash.
- **[MAJOR] §4.6** — Zombie process leaks from parent-only kills
  - fix: Agent CLIs spawn subprocesses (shells, compilers); `child.kill('SIGTERM')` leaves them orphaned. The spawn utility must use `detached: true` and kill the entire process group with `process.kill(-child.pid, 'SIGTERM')`.
- **[MAJOR] §8** — apply-patch refusing dirty workspaces breaks Review mode
  - fix: If a user applies a patch from one candidate, the workspace becomes dirty, blocking application of further patches. The strict dirty check must be removed, relying instead on `git apply --3way` conflict detection.
- **[MAJOR] §5** — Worktrees ignore uncommitted user WIP
  - fix: Branching from `HEAD` silently discards uncommitted changes in the user's workspace, confusing the agent. The engine must fail-fast if worktree isolation is used on a dirty repo, or temporarily stash/commit the changes before branching.
- **[MAJOR] §3.1** — 500ms append-only coalescing shatters UI rendering
  - fix: Because events are append-only, flushing token deltas every 500ms will cause the UI to render hundreds of separate message/thinking bubbles for a single stream. The UI store must merge contiguous events with the same `nodeRunId`, `role`, and `kind`.
- **[MAJOR] §4.1** — Claude adapter attempts to read non-existent resultText
  - fix: The spec assumes Claude's final result event contains the full text block. It does not. Adapters must accumulate text internally during streaming and synthesize the final `resultText` upon exit.
- **[MINOR] §4.4** — agy buffering destroys live-streaming UX
  - fix: Waiting for the agy process to exit before emitting a single message event means the UI will show a dead spinner for minutes. The adapter must emit `message` chunks dynamically as stdout lines arrive.
- **[MINOR] §3.1** — Missing toolCallId prevents tool correlation
  - fix: Agents can execute tools in parallel, but `AgentEvent.tool` lacks an ID. Add `toolCallId: string` to the payload so the UI can reliably match `tool_result` events back to their initiating `tool_use`.
- **[MINOR] §7** — Server restart permanently orphans running runs
  - fix: If the server crashes and restarts, runs in `running` or `gating` states loaded from `runs.json` will wait forever. On startup, the engine must sweep and transition these to `failed` (engine crash).
- **[MINOR] §6** — Orchestrator retry crashes on hallucinated NodeRunIds
  - fix: If the orchestrator LLM outputs a hallucinated or out-of-scope `retryNodeRunIds`, the engine will hang or crash. The engine must validate requested IDs against the current stage's actual nodes before attempting a retry.
- **[MINOR] §3.1** — Async sequence assignment race condition
  - fix: If adapters fire events concurrently and WS broadcasts independently of disk I/O, events may be delivered out-of-order of their `seq`. `eventLog.ts` must use an atomic queue for sequence assignment, file appending, and WS broadcasting.

## grok-4.5 — verdict: revise

VERDICT: revise — The architecture and locked decisions are sound, but several contracts that parallel workers must share (RunCreate overrides, event stamping/status shape, nodeRunId/retry identity, artifact handoff, listen host) are still ambiguous or wrong for the stated user story and Build Mode. Close those with normative types and engine rules in shared/ before one-shot implementation; otherwise integrate wave will be a rewrite, not a glue pass.

- **[BLOCKER] §8/§3.2/§9** — `POST /api/runs` body leaves `overrides?` untyped while §1 requires drag/edit agents, model, effort, then Run; web and store-api will invent incompatible shapes and the primary start path breaks.
  - fix: Normatively define `RunCreateRequest` in `shared/src/api.ts`, e.g. `{ workspaceId, workflowId, task, workflowOverride?: WorkflowDef | { stages: PartialStage[] }, orchestratorEnabled?: boolean }`, with zod; UI must send the fully resolved workflow snapshot used for that run (immutable copy under `runs/<id>/workflow.json`).
- **[BLOCKER] §3.1/§3.3/§5** — `nodeRunId` format conflicts (`roundtable.grok.2` vs `${stageId}.${slotId}.${i}`) and retry does not say whether ids are reused, events/raw append or overwrite, or how `attempt` / `retryNodeRunIds` stay stable.
  - fix: Lock `nodeRunId = `${stageId}.${slotId}.${instanceIndex}`` (0-based, immutable across retries); on retry bump `attempt`, append to same `raw/<nodeRunId>.jsonl` and event stream with new `status:spawned`; forbid provider names in the id; document join re-waits only on requeued ids.
- **[BLOCKER] §3.1/§4.0** — Status/result/error payloads and stamping responsibilities are underspecified: no `data.status` enum field, no required `role`/`kind` pairs for lifecycle events, and adapters emit without `runId`/`nodeRunId` while UI depends on them.
  - fix: Add normative mapping table: `kind:'status'` + `role:'system'` + `data:{ status: NodeRunStatus|'spawned', detail?: string }`; `kind:'result'` + `role:'system'` + `data:{ exitCode, usage?, sessionRef? }`; `kind:'error'` + `role:'system'`; require `nodeRunner` (not adapters) to assign `id/seq/runId/stageId/nodeRunId/ts` before `eventLog.append`.
- **[BLOCKER] §5/§6.2/§10** — Cross-stage worktree artifacts never enter the next stage: templates lack patch/artifact vars, engine never applies patches into reviewer cwd, so Build Mode "review the patches" sees an empty main tree.
  - fix: Define stage handoff: on advance from `isolation=worktree`, either (a) inject `{{patches}}` / `{{artifact_paths}}` (full patch text up to a hard cap) into next-stage prompts, or (b) materialize `artifacts/` into a read-only review worktree and set reviewer `cwd` there; presets must use the chosen mechanism.
- **[BLOCKER] §2/§1** — Server bind host is implied localhost-only; §1 is browser-over-Tailscale to castle1, so a `127.0.0.1` Fastify listen makes the product unreachable remotely.
  - fix: Spec `mat-server --host 0.0.0.0|--host <ip>` (default `0.0.0.0` on fleet, or document Tailscale IP bind), put host in `settings.json`, and state v1 auth = network trust only (no cookie auth).
- **[MAJOR] §4.0** — `SpawnedNode` / `NodeOutcome` are comment-only; adapters, engine kill/timeout/join, and tests cannot share one completion contract.
  - fix: Export: `NodeOutcome = { exitCode: number|null; signal?: string; sessionRef?: string; usage?: Usage; resultText?: string; error?: string }`; `SpawnedNode = { pid: number; kill(sig?: NodeJS.Signals): void; completion: Promise<NodeOutcome> }`; engine treats `completion` settle + final status event as terminal.
- **[MAJOR] §7/§5/§11** — Crash recovery omitted: after server restart, runs left `running`/`gating` with dead child PIDs; acceptance only covers finished-run replay.
  - fix: On boot, mark any non-terminal run `failed` (or `aborted`) with system event `server_restart`, clear live process table; do not auto-resume CLI children in v1; document explicitly.
- **[MAJOR] §0.8/§8** — Mid-run "retry stage" is in-scope human intervention but has no REST endpoint or engine entrypoint (only abort/kill/apply-patch).
  - fix: Add `POST /api/runs/:id/retry-stage` `{ stageId, promptAddendum? }` allowed only when status is `gating` or stage fully terminal; requeues all stage nodes (or last `retryNodeRunIds`) under same maxRetries budget.
- **[MAJOR] §7/§3.1** — Concurrent multi-node append to `events.jsonl` and seq assignment lack a single-writer rule; parallel workers will race seq or corrupt JSONL.
  - fix: Mandate one per-run mutex/queue in `eventLog`: all appends (nodes, stall, orchestrator, system) serialize through it; seq = previous+1; WS broadcast only after durable append.
- **[MAJOR] §3.2/§4.4/layout** — `gemini` is a first-class `AgentBinding.provider` and `gemini.ts` exists, but only `agy` is specified; one-shot builders will fork or leave a stub that the palette still offers.
  - fix: Either alias `gemini → agy` in registry (single adapter, two ids) with one permission/model table, or drop `gemini` from v1 provider union and presets.
- **[MAJOR] §5/§6** — Retry/resume policy missing: adapters support `resumeSessionRef`, but retry only mentions `prompt+addendum`; wrong default poisons plans or loses thread state.
  - fix: Default retries to fresh session (`resumeSessionRef` unset) + full rendered prompt + `{{retry_addendum}}`; optional `Slot.resumeOnRetry?: boolean` (default false); orchestrator alone always resumes when provider supports it.
- **[MAJOR] §4/§6** — Long prompts passed as CLI argv (`claude -p`, `codex exec`, `grok -p`) will hit `ARG_MAX` on real tasks/digests; silent spawn failures.
  - fix: Require prompt delivery via temp file or stdin where CLI allows (`@file` / stdin prompt flags); if only argv works, hard-cap with clear `error` event and document max size; never embed 24k digests solely on argv without a file fallback.
- **[MAJOR] §3.3/§6/§9** — Orchestrator is a special `nodeRunId: "orchestrator"` decision stream and "node card" but is not a `NodeRun` in `nodes[]`, so run panel/stream filters and kill semantics diverge across web-run vs engine.
  - fix: Always insert a synthetic `NodeRun` `{ nodeRunId: 'orchestrator', slotId: 'orchestrator', … }` into `RunSnapshot.nodes`; gate decisions still live in `gateDecisions` and as `kind:'decision'` events on that node.
- **[MAJOR] §1/§9** — Product intro/user story promise live streams "side by side"; UI is one aggregated feed with filters—builders will either under-deliver the story or invent a second layout.
  - fix: Amend §1/§9: v1 = single virtualized aggregated stream + node multi-filter (focus-stream from card); defer true multi-column per-agent panes to v1.1 so wave-1 web does not scope-creep.
- **[MAJOR] §4.3/§11** — Grok tool event mapping is "verify against live output / implementer probe"; Wave-1 adapters + exact fixture tests cannot land deterministically without pinned schema.
  - fix: Before fleet start, check in `server/test/fixtures/grok.jsonl` (incl. at least one tool call) and a frozen type→event table in §4.3; tests assert that table only—no live probe in the critical path.

## claude-fable-5 — verdict: revise

Spec is faithful to the 12-round debate consensus on all 8 locked decisions (verified against the full transcript; only two quiet divergences: plain-tier replacing the agreed read-only raw-PTY fallback, and dropping the round-12 "reuse BAT peripheral scaffolding" advice for a from-scratch server), and the architecture within the locked decisions is sound. But a one-shot fleet build would fail its own acceptance bar today: no one is assigned to emit the 'user'-category events the product is named for, the "REAL fixtures" the test suite mandates exist only in /tmp/mat-probes (contaminated with 2>&1 stderr), and the existing grok tool-probe disproves §4.3's tool-event mapping. The §12 split additionally hides cross-module seams (NodeOutcome, seq-assignment/broadcast ordering, mock-adapter contract, shared web components owned by the wrong worker) that would force divergence between wave-1 workers. Fix the two blockers plus the contract pins and this is buildable in one shot.

- **[BLOCKER] §3.1/§6.2/§11** — No component is specified to emit the 'user' role event carrying each node's rendered prompt: adapters only map CLI stdout, and verified probes show no CLI echoes the prompt in its stream (claude.jsonl has zero type:user lines; codex/grok/agy likewise). W-adapters and W-engine will each assume the other does it, leaving the 'your' category — one of the four headline categories in §0/§1 — permanently empty and failing the §11 smoke assertion '≥1 event of each category'.
  - fix: Add to §3.1 rules: the engine (nodeRunner) synthesizes a role:user/kind:message event containing the final rendered prompt at every node spawn and retry (with the addendum), before status:spawned events flow; add it to the mock adapter's scripted sequence so engine/API tests enforce it.
- **[BLOCKER] §11/§12** — Unit tests mandate parsing 'checked-in REAL fixtures' but the repo contains only SPEC.md, server/test/fixtures/ is assigned to no §12 worker, and an autonomous fleet cannot capture real outputs without provider credentials. The actual probes exist only at /tmp/mat-probes on castle1, and they were captured with 2>&1 — stderr banners ('Reading additional input from stdin...', claude's stdin warning) and probe-artifact 'exit=N' trailer lines are interleaved into the JSONL, so even copying them verbatim breaks strict parsers; the spec also never states a policy for non-JSON stdout lines (one builder will skip them, another will emit kind:error per line).
  - fix: Vendor the probe captures into server/test/fixtures/ as part of wave-0 scaffold (spec their source path explicitly), re-capture or clean them with stdout/stderr separated per the §7 raw format, and add a §4.0 rule: non-JSON stdout lines are silently skipped for normalization but always appended to the raw log.
- **[MAJOR] §4.3** — The grok tool-event mapping is speculative and disproved by the existing probe: grok-tool.jsonl (a tool-using run, captured 06:02 — after SPEC.md was written) contains ONLY thought/text/end events; the shell command executed invisibly between thought tokens. Builders told to map 'tool_call/tool_result-like types' will either block waiting for a live probe they cannot run (no creds) or fabricate mappings for events that never occur, and grok nodes will show zero tool activity plus long silent gaps during tool execution.
  - fix: Pin §4.3 to the probe: grok streaming-json emits no tool events in v1 — delete the speculative mapping, state tool-call count is unavailable for grok in the §5.1 digest, check in grok-tool.jsonl as the fixture of record, and note the silent-gap implication for stall handling.
- **[MAJOR] §4.0/§12** — The server-side wave-1 seams are undefined: SpawnedNode/NodeOutcome are referenced but their fields never specced (who carries exitCode/resultText/usage/sessionRef — outcome vs result event, and in which casing, given §4.1 writes input_tokens while NodeRun.usage is camelCase); who assigns id/ts vs seq ('event log' per §7) and whether wsHub broadcast happens before or after seq assignment (if before, afterSeq catch-up misses/duplicates events); and the routes→engine control surface (startRun/abortRun/killNode) crossing W-store-api→W-engine is unspecified. Three owners share one event pipeline with no pinned interface.
  - fix: Add a §12.1 'internal seams' block that wave-0 stubs must implement verbatim: define NodeOutcome {exitCode: number|null, resultText?, usage? (camelCase), sessionRef?, error?}; store.appendEvent(runId, partial) synchronously assigns id/seq/ts and returns the full AgentEvent, and only then wsHub.broadcast(event) fires; pin role for status/result/error events (system); enumerate the engine control interface consumed by routes.
- **[MAJOR] §12/§9** — Web ownership split has hidden coupling: web/src/components/** (AgentChip, ModalDialog, StatusDot, Collapsible) is exclusive to W-web-run, but W-web-shell's workflow panel requires AgentChip for slot chips (§9.2) and ModalDialog for the add-workspace dialog (§9.1); likewise app/store.ts (zustand) is W-web-shell's, but W-web-run's stream filters and the run panel's focus-stream button must add/dispatch store state. Two same-wave workers are blocked on each other's exclusive files and will fork duplicate components/stores.
  - fix: Move web/src/components/** and the complete zustand store interface (state shape + action signatures incl. filters and focusNode) into wave-0 scaffold as working code frozen for wave 1; same for the mock adapter's config contract (scripted sequence, delay/failure knobs) which W-adapters, W-engine tests, and W-store-api's --demo all depend on.
- **[MAJOR] §5/§3.3** — Retry semantics are ambiguous on three axes independent builders will resolve differently: (a) fresh spawn with re-rendered template + {{retry_addendum}} vs --resume sessionRef with the addendum as the new prompt (both mechanisms exist in the spec); (b) whether the retried NodeRun is mutated in place (attempt++, resultText/startedAt overwritten) or a new NodeRun appended; (c) events carry no attempt marker, so replay cannot segment attempt 1 from attempt 2 under the same nodeRunId.
  - fix: Specify: retry = fresh spawn (no resume for candidates in v1), full template re-render with {{retry_addendum}} filled; same NodeRun mutated with attempt+1; engine emits a status event {detail:'retry', data:{attempt}} at each attempt boundary and adapters' events between boundaries belong to that attempt.
- **[MAJOR] §6** — The orchestrator must 'render as a node card too, with its own stream' under nodeRunId 'orchestrator', but it has no NodeRun in RunSnapshot.nodes — its id violates the `${stageId}.${slotId}.${i}` format and NodeRun.stageId is non-nullable — so W-web-run has no data source for its status/elapsed/usage card. Separately, the orchestrator's own CLI turn has no timeout: a hung gate spawn leaves the run in 'gating' forever (stages have timeoutSec; gates have nothing).
  - fix: Make NodeRun.stageId nullable and add a reserved orchestrator NodeRun (nodeRunId 'orchestrator', slotId 'orchestrator') maintained across gates, or add a RunSnapshot.orchestrator field with the same status shape; add gateTimeoutSec (default 300) after which the decision falls back to advance with degraded:true.
- **[MAJOR] §5** — Worktree patch capture 'git diff (vs stage base)' misses untracked files: agents implementing features create new files, which plain `git diff` excludes, so Build Mode patches silently drop every newly created file and apply-patch reconstructs a broken change.
  - fix: Specify the capture command: `git -C <wt> add -A && git -C <wt> diff --cached <baseCommit>` (record baseCommit = HEAD at worktree add), with binary diffs enabled (--binary) so apply --3way round-trips.
- **[MAJOR] §3.1** — Coalescing 'flushed on type-change or ≥500 ms' over an append-only event log means a single continuous grok thinking burst becomes ~2 events/second of fragments; there is no event-update semantics (WS has no patch message, events.jsonl is append-only), so some builders will mutate/replace the last event (breaking replay and afterSeq) while others append fragments the stream panel then renders as dozens of broken 2-line thinking rows.
  - fix: State explicitly: events are immutable and each flush appends a new event; the EventRow renderer MUST visually merge runs of consecutive events with the same nodeRunId+kind into one block (same rule applied in digest assembly), and per-flush events set data:{continued:true} after the first.
- **[MAJOR] §5/§7** — No crash/restart recovery: if the server dies mid-run, run.json persists status 'running'/'gating' forever (permanent live pulse in the rail, Start disabled state confusion), agent child processes are orphaned, and worktrees/branches leak; §11 only guarantees replay of finished runs. DELETE /api/runs/:id on a live run is likewise unspecified and would rip directories out from under writing processes.
  - fix: Specify: persist child PIDs in run.json; on boot, sweep runs with non-terminal status → mark 'aborted' (status event detail 'server-restart'), best-effort SIGKILL recorded PIDs, prune their worktrees; server SIGTERM handler kills children; DELETE on a non-terminal run returns 409 (or aborts first).
- **[MAJOR] §8/§1** — POST /api/runs 'overrides?' has no defined shape anywhere, yet the §1 story depends on it: builtins are immutable and §9.2 forces 'Duplicate to customize', so Ted's canonical flow (drag codex + two grok chips onto builtin Planning Mode, tweak a model, Run) either can't happen as narrated or every builder invents a different overrides schema (W-store-api validation vs W-web-shell payload divergence guaranteed).
  - fix: Define overrides as a complete inline WorkflowDef snapshot (zod-validated, executed as-is and persisted into run.json for replay); UI keeps an ephemeral edited copy of a builtin and submits it via overrides without forcing duplication — 'Duplicate to customize' remains only for saving.
- **[MAJOR] §0.8/§8** — 'Retry stage' is one of the four human interventions explicitly kept in scope by locked decision 8, but it appears nowhere else: no REST endpoint in §8, no button in §9.3, no engine transition in §5 for a user-initiated (vs gate-decided) retry — an internal contradiction the fleet cannot resolve.
  - fix: Add POST /api/runs/:id/stages/:stageId/retry (valid while gating or after run reaches a terminal state at/after that stage; re-enters the stage as a full retry attempt, subject to maxRetriesPerStage) plus a retry button on stage group headers — or amend §0.8 to drop it deliberately.
- **[MAJOR] §5/§4.4** — Stall detection ('no adapter events for stallSec', default 120s) false-positives on healthy nodes constantly: agy emits nothing between spawn and exit (plain tier — minutes of silence, so every agy node shows 'stalled' ~100% of its runtime), grok emits nothing during tool execution (probe-confirmed), and claude/codex are silent during any long tool call; operators will learn to ignore the amber badge, killing the feature. This is also where the spec quietly departs from the debate consensus, which kept a live read-only raw view for non-JSONL CLIs.
  - fix: Base the stall timer on raw stdout/stderr line activity (onRaw) rather than normalized events, raise the plain-tier default (e.g. stallSec 600 for agy), and stream agy stdout incrementally as chunked agent text instead of one message at exit so the panel shows liveness.
- **[MINOR] §4.2/§3.4** — Non-git workspaces break codex and the UI contract: the real probe required `--skip-git-repo-check` to run codex exec in a non-git cwd (spec's §4.2 command omits it, so codex nodes fail in non-git workspaces the spec explicitly supports), and Workspace has no isGit field even though §9.1 shows an is-git flag and §5's worktree fallback needs it.
  - fix: Add `--skip-git-repo-check` to the codex adapter invocation (unconditionally is safe), and add isGit: boolean to Workspace, computed server-side at registration and refreshed on read.
- **[MINOR] §0/§2** — Debate-fidelity audit: the 8 locked decisions are all traceable to the round-9–12 consensus (verified against the 12-round transcript incl. Ted's interjections), but two consensus points were silently altered — the agreed fallback for non-JSONL CLIs was a read-only raw-PTY pane (spec substitutes the 'plain' tier), and round 12's unanimous 'reuse BAT peripheral scaffolding (Worker/Procfile lifecycle, worktree, session)' was replaced by a from-scratch Fastify server with the rationale placed in §2 but never marked as a post-debate deviation.
  - fix: Add one line to §2: 'Deviation from debate round 12: BAT scaffolding reuse was dropped because BAT is Tauri-bound (xvfb on headless fleet); its lifecycle/worktree patterns are re-specified natively here' — and note in §0.3 that the plain tier supersedes the debated raw-PTY fallback per locked decision 2.
